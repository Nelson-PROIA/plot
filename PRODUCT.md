## 1. The problem

Code production has outpaced code understanding.

- LLMs ship more code, faster, than ever — and PR volume grows with it.
- Reviewers (especially juniors) face diffs they didn't write, generated by tools
  they didn't watch work, in systems they only partially understand.
- The result is **blind approval**: low confidence, stress, "yes-yes-yes" through
  review without learning anything.
- Existing AI reviewers (CodeRabbit, Greptile, Cursor review…) are themselves LLMs
  summarizing diffs — models reviewing models. They go *deep on the diff*; they do
  not make the *human* understand the *system*. The trust problem is unchanged.
- Humans are now the bottleneck in the loop — not because review is slow, but
  because **understanding** is.

## 2. The bet (north star)

**Plot is a human-understanding tool, not a bug-finder.**

The differentiator is *abstraction*: take a repository and its open PRs and render
them at the altitude a human actually thinks at — systems talking to systems,
files importing files, functions calling functions, data flowing through code —
and let the reviewer *choose their altitude* fluidly.

- Deep diff analysis is a solved problem (and others' problem). We don't compete there.
- We make **human-in-the-loop review** mean something again: the reviewer should
  *understand and learn*, not gatekeep.
- Explicit audience bias: **juniors** entering an industry where AI writes most
  code — Plot is also a learning tool. Review becomes education.

Tagline (hackathon era, still holds): *Turn every PR into a story you can navigate.*

## 3. Product principles

1. **One view.** Onboard a repo → it becomes a knowledge base → a single canvas.
   No separate “graph page” vs “PR page” mental model. Everything is the repo
   graph; PRs, traces, and AI live as overlays/panels on it.
2. **Granularity is the navigation primitive.** Scroll = abstraction ladder
   (up = more abstract, down = more granular). Spatial zoom is secondary (⌘+scroll).
3. **The knowledge base is the product's foundation.** Ingestion must be deep and
   smart; it's OK if it takes time. It must be a *real*, incrementable KB
   (stable IDs, delta-patchable) — cron/webhook sync is an easy later add.
4. **PRs are first-class overlays.** Select one or several PRs and *see* what they
   impact at any altitude. Default: rest of graph softly dimmed; toggle to isolate.
5. **Data flow is how people understand code.** “Start data from here” and watch
   it move through the graph. Keep and grow this — 100%.
6. **Never lose features in a refactor — reorganize them.** Re-interface, don't drop.
7. **Edges are the point.** A knowledge graph with invisible relations is a list.
   It's OK for the canvas to be big and dense — that *is* the product.

## 4. The granularity ladder

| Level | Key | Nodes | Edges | Question it answers |
|---|---|---|---|---|
| **System** | `1` | Logical groups (top dirs, descending into `src/`, `packages/`…) as bubbles | Aggregated import flows, weighted | "What are the parts of this thing and who talks to whom?" |
| **File** | `2` | Files, dagre-laid by import topology, group hulls | File→file imports, colored by source group | "How is this wired together?" |
| **Symbol** | `3` | Exported functions/components/classes/types | Symbol→symbol call edges | "Who calls what?" |
| **Code** | `4` | Source-excerpt cards (body of each symbol) | Call edges between cards | "What does it actually do?" |

Interactions (current): plain scroll climbs/descends the ladder; ⌘+scroll spatial
zoom; `1–4` jump; double-click a system bubble dives in; ▶ on any symbol/code node
starts an AI data-flow trace; click/shift-click PRs in the legend to focus one or
many; `dimmed ↔ isolated` toggle when a focus is active.

## 5. What exists today (verified, branch `unified-graph`)

**Unified canvas (`/`)** — all four levels implemented; PR multi-select with
union-of-files highlighting; per-PR colors; hide-vs-dim toggle; legend with groups
+ PRs (focus / add-to-selection / describe-with-AI); minimap; presentation mode.

**Knowledge graph (server-side `/api/repo/graph`)** — GitHub tree walk (≤250
files), tsconfig-alias-aware import resolution, regex symbol extraction
(functions/components/classes/types/enums/consts + line numbers), symbol→symbol
call-edge inference (import bindings + usage scan), group derivation that descends
into `src/&co`. CDN-cached 1h (+24h SWR), localStorage-cached client-side 1h.
Reference numbers: this repo ingests as 68 files / 137 symbols / 150 import edges /
185 call edges, ~1.5–2.5s cold, ~30ms cached.

**AI layer (OpenAI, gpt-4o-mini)** — PR canvas enrichment (intent / risks /
alternatives / change diagrams, streamed, cached by head SHA); function data-flow
trace (callers/callees with example payloads, animated packet walk, drill-down +
breadcrumbs); file explainer; context-aware chat assistant (repo / PR / node
scopes); cross-PR risk audit panel.

**Per-PR canvas (`/pr/[n]`)** — 7 node types (intent, architecture, change cards
with before/after mermaid, alternatives carousel, risk pins, diff, live preview
iframe), guided tour with autoplay, progressive reveal, approve + merge.
Also surfaced as a compact right-side drawer on the unified canvas.

**Infra** — GitHub proxy (`/api/gh/*`) with server-held token (never reaches the
browser); raw.githubusercontent.com for content; deployed on Vercel
(`plot-orpin.vercel.app`).

## 6. Known gaps & honest quality notes

- **Parsing is regex, not AST.** Good enough to demo; misses re-exports, namespace
  imports, dynamic dispatch, methods, non-exported symbols. The KB deserves a real
  parser (SWC/tree-sitter/ts-morph) server-side. Biggest single quality lever.
- **Call-edge inference is heuristic** (identifier match within approximate
  scopes) — produces some false positives/negatives; type-only “calls” conflated
  with runtime calls.
- **Level transitions are crossfades, not morphs.** No spatial continuity between
  levels yet (collapse-into-parent / explode-from-parent animation).
- **Layout**: dagre is static; no force simulation, no continuity of node identity
  across levels; large repos (>250 files) truncated.
- **Incrementality is schema-ready but not wired** — no webhook/cron resync yet.
- **Data-flow trace is AI-inferred**, not derived from the KB's call edges — the
  two should converge (trace along *real* edges, AI annotates payloads).
- **Single language family** (TS/JS + light HTML/CSS). Python/Go/etc. later.
- **Mock mode** exists but is stale relative to the unified canvas.

## 7. MVP roadmap (proposal — iterate here)

### Phase A — Trustworthy knowledge base (the moat)
- [ ] Replace regex extraction with real parsing (SWC or tree-sitter on the server).
- [ ] Resolve symbols & calls semantically; keep stable IDs (`file::symbol`).
- [ ] Persist the KB server-side (KV/Postgres) instead of CDN-cache-only;
      version it; delta-patch on webhook push events.
- [ ] Lift the 250-file cap via pagination/sharding of ingestion.

### Phase B — The canvas feels like one continuous world
- [ ] Morphing level transitions (nodes expand/collapse from parents).
- [ ] Stable spatial anchoring (a group's files appear *where the bubble was*).
- [ ] Edge bundling / hover-emphasis so dense graphs stay legible.
- [ ] Search ("go to file/symbol") + permalink to a node at a level.

### Phase C — Review workflow on the graph
- [ ] PR overlay: changed nodes get added/modified/deleted states (not just tint).
- [ ] Inline diff peek on a changed file/symbol node.
- [ ] Walk a PR as a graph tour (today's tour, but on the unified canvas).
- [ ] Approve/comment from the canvas; review state synced to GitHub.

### Phase D — Understanding tools
- [ ] Data-flow trace v2: animate along *KB* edges, AI annotates payloads.
- [ ] "Explain this neighborhood" — AI summary of any selection/cluster.
- [ ] Architectural drift alerts (new cross-group edges = boundary violations).
